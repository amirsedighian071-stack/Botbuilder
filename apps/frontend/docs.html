مستندات BotForge

از راه‌اندازی محلی تا استقرار خودکار روی Cloudflare Workers و Railway. همه دستورها و نمونه‌های کد قابل کپی هستند.

شروع راه‌اندازی سریع معماری مونوریپو تنظیمات محیطی محصول ۳۲ ربات و دسته‌ها ویزارد و استقرار خودکار عضویت اجباری مرجع مرجع API استقرار خودکار بسته استقرار امنیت عیب‌یابی

راه‌اندازی سریع

این سایت کاملاً ایستا است: ویزارد، بسته استقرار را در همان مرورگر می‌سازد و هیچ سروری برای ساخت ربات لازم نیست. برای اجرای محلی همین سایت: 

git clone https://github.com/amirsedighian071-stack/Botbuilder.git
cd Botbuilder
npm install
npm run build
node scripts/serve-frontend.mjs --port 4173 --host 0.0.0.0

مهم‌ترین خروجی ساخت، dist/install/main.js است: یک سرویس تک‌ربات که همه چیزش از متغیرهای محیطی خوانده می‌شود. همان فایل در بسته‌های Cloudflare و Railway استفاده می‌شود: 

BOT_TEMPLATE=gold-price \
BOT_PLATFORM=telegram \
BOT_TOKEN='123456:AA...' \
BOT_SLUG=gold-price \
BOT_NAME='قیمت طلا' \
BOT_CONFIG_JSON='{"defaultCity":"Tehran"}' \
SECRET_MASTER_KEY='کلید-۳۲-کاراکتری' \
JWT_SECRET='کلید-امضای-توکن' \
ADMIN_SEED_EMAIL='admin@example.com' \
ADMIN_SEED_PASSWORD='گذرواژه-قوی' \
PORT=8080 node dist/install/main.js
در اولین اجرا چه می‌شود سرویس جدول‌ها را می‌سازد، رکورد ربات را ثبت می‌کند، توکن را با کلید اصلی رمزنگاری می‌کند و آدرس وب‌هوک را روی پلتفرم ثبت می‌کند. نشانی سلامت در /health و ورود مدیر در POST /api/auth/login است.

معماری مونوریپو

ساختار پوشه‌ها عمداً ساده و قابل نگهداری است:

packages/
  core/               ابزار مشترک، تنظیمات، اعتبارسنجی، ذخیره‌سازی
  platform-adapters/  آداپتور تلگرام، بله، روبیکا
  engine/             موتور اجرا، مدیریت ربات، صف کار، وب‌هوک
  bot-templates/      ۳۲ قالب ربات و کاتالوگ
apps/
  control-plane/      API Fastify + سرویس install (تک‌ربات) + استقرار
  cloudflare-worker/  نسخه ورکر برای استقرار لبه‌ای
  frontend/           سایت چندصفحه‌ای ایستا + ویزارد سازنده بسته
scripts/              ساخت، تولید کاتالوگ، سرور پیش‌نمایش

لایه ذخیره‌سازی با یک قرارداد مشترک پیاده شده است: SQLite برای توسعه، PostgreSQL برای تولید و D1 برای ورکر. هر ربات شناسه مستقل دارد و همه پرس‌وجوها به همان شناسه محدود می‌شوند.

موتور و آداپتور

موتور، پیام‌های نرمال‌شده را دریافت می‌کند و منطق قالب را اجرا می‌کند. تفاوت‌های هر پلتفرم داخل آداپتور پنهان است؛ به همین دلیل یک قالب روی تلگرام، بله و روبیکا یکسان کار می‌کند. 

packages/platform-adapters/src/index.ts   // createAdapter, detectPlatformFromToken
packages/engine/src/manager.ts            // createBot, reload, webhookUrl, registerWebhook
packages/engine/src/runtime.ts            // اجرای دستورها، میان‌افزارها، محدودیت نرخ

هر بسته استقرار یک ربات را توصیف می‌کند؛ ویزارد همه این متغیرها را در فایل .env می‌نویسد:

متغیرالزامیتوضیح
BOT_TEMPLATEبلهشناسه قالب از کاتالوگ ۳۲ رباتی
BOT_PLATFORMبلهیکی از telegram، bale یا rubika

کلیدها را در مخزن نگذارید فایل .env بسته فقط روی رایانه شما ذخیره می‌شود و .gitignore بسته آن را نادیده می‌گیرد. رمزها را در پنل میزبان یا wrangler secret وارد کنید.

۳۲ ربات و دسته‌ها

کاتالوگ در پنج دسته سازمان‌دهی شده و هر ربات دستورها و کلیدهای مشخص خود را دارد:

دستهتعدادربات‌ها
مالی و اطلاعاتی (A)۵قیمت طلا و ارز، رمزارز، اخبار، هشدار قیمت، آب‌وهوا، ماشین‌حساب مالی
فروش و کسب‌وکار (B)۷فروشگاه، پشتیبانی، نوبت‌دهی، اشتراک، بازاریابی، سفارش خدمات، CRM
دانلود و رسانه (C)۸دانلود اینستاگرام و یوتیوب، موسیقی، تبدیل صوت، فایل، فرمت، گفتار
هوش مصنوعی (D)۵دستیار هوشمند، مترجم، دستیار مطالعه، تولید محتوا، خلاصه‌ساز SSRF-safe
مدیریت و ابزار (E)۷مدیریت گروه، نظرسنجی، یادآور، کوتاه‌کننده لینک، فرم‌ساز، دوره، پایش سایت

فهرست دقیق با شماره، دستورها و کلیدها در صفحه کاتالوگ آمده است. منبع واقعی قالب‌ها در packages/bot-templates/src است و کاتالوگ سایت با node --import tsx scripts/generate-catalog.mjs از همان منبع ساخته می‌شود.

ویزارد و استقرار خودکار

ویزارد چهار مرحله دارد. هیچ سروری از شما خواسته نمی‌شود: نه آدرس سرویس، نه ایمیل مدیر، نه ورود به پنل واسط.

  1. انتخاب یکی از ۳۲ قالب با جست‌وجو و فیلتر دسته‌بندی.
  2. انتخاب پلتفرم (تلگرام، بله، روبیکا) و توکن ربات؛ توکن در صورت دسترسی شبکه، با getMe بررسی می‌شود و در غیر این صورت فقط الگوی آن اعتبارسنجی می‌شود.
  3. ورود کلیدهای یکپارچه‌سازی همان قالب، همراه با لینک مستقیم صفحه رسمی ساخت کلید.
  4. نام و شناسه ربات، انتخاب میزبان و دکمه «ساخت و استقرار خودکار».

در پایان، بسته کامل به‌صورت ZIP دانلود می‌شود: فایل‌های متغیر محیطی، اسکریپت استقرار، تنظیمات میزبان و آدرس آماده وب‌هوک. توکن و کلیدها فقط در حافظه همان تب پردازش می‌شوند.

عضویت اجباری

در داشبورد هر ربات، بخش «عضویت اجباری» را باز کنید. هر کانال شامل پلتفرم، شناسه چت، عنوان، لینک دعوت و وضعیت الزامی بودن است. ربات پیش از اجرای دستور، عضویت کاربر را بررسی و در صورت نبود عضویت، لینک ورود می‌فرستد. 

curl -X PUT "https://SERVER/api/bots/BOT_ID/force-membership" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "enabled": true,
    "channels": [
      {
        "id": "ch_1",
        "platform": "telegram",
        "chatId": "@botforge_channel",
        "title": "کانال رسمی BotForge",
        "inviteLink": "https://t.me/botforge_channel",
        "required": true
      }
    ]
  }'

استقرار خودکار

استقرار روی Cloudflare با یک دستور در پوشه بسته انجام می‌شود. اسکریپت به‌ترتیب پایگاه‌داده D1 را می‌سازد، طرح‌واره و رکورد ربات را وارد می‌کند، رمزها را به‌عنوان secret ثبت می‌کند، ورکر را منتشر می‌کند و وب‌هوک را روی پلتفرم ثبت می‌کند: 

bash deploy.sh
# یا معادل آن:
npx --yes wrangler deploy
npx --yes wrangler d1 execute botforge-gold-price --remote --file=schema.sql --yes

روی Railway، همان پوشه با railway.json و Dockerfile ساخته می‌شود؛ ایمیج، dist/install/main.js را اجرا می‌کند و متغیرها از .env تنظیم می‌شوند: 

bash deploy.sh
# جایگزین بدون CLI:
docker compose up -d --build

پس از استقرار، آدرس /health سرویس را در صفحه استقرار ثبت کنید تا کد پاسخ، تأخیر و نسخه سرویس نمایش داده شود.

دسترسی‌های لازم

توکن Cloudflare باید دسترسی Workers Scripts:Edit، D1:Edit و Account Settings:Read داشته باشد. توکن Railway از صفحه Account Tokens ساخته می‌شود و فقط به پروژه‌های همان حساب دسترسی دارد.

بدون واسطه توکن میزبان و توکن ربات هرگز به سرور شخص ثالثی فرستاده نمی‌شوند؛ فقط در همان تب مرورگر برای تولید فایل‌های بسته استفاده می‌شوند و در بسته ZIP ذخیره می‌شوند.

بسته استقرار

هر ZIP شامل این فایل‌ها است:

فایلکار
.env و .env.exampleهمه متغیرهای BOT_* و رمزهای تولیدشده
deploy.shاسکریپت استقرار مخصوص میزبان انتخابی
wrangler.toml + schema.sql + bot-row.sqlپیکربندی ورکر، طرح‌واره D1 و رکورد آماده ربات

فایل‌های حاوی رمز را در محیط امن نگه دارید. صفحه داشبورد می‌تواند بسته را با همان مقادیر دوباره بسازد، به‌شرط آنکه نشست مرورگر باز مانده باشد؛ در غیر این صورت یک نصب تازه بسازید.

امنیت

  • توکن ربات با کلید اصلی رمزنگاری و فقط به‌صورت ماسک نمایش داده می‌شود.
  • پرس‌وجوهای SQL پارامتری‌اند؛ ورودی‌ها با zod اعتبارسنجی و متن‌ها پاک‌سازی می‌شوند.
  • محدودیت نرخ روی ورود، ارسال همگانی و وب‌هوک اعمال می‌شود.
  • خلاصه‌ساز لینک و درخواست‌های بیرونی با محافظ SSRF، DNS و بلاک شبکه خصوصی اجرا می‌شوند.
  • هر وب‌هوک دارای کلید مخفی در مسیر است و بدون آن پردازش نمی‌شود.
  • لاگ‌ها و رکوردهای حسابرسی، عملیات مدیران را ثبت می‌کنند.
کلیدهای API فقط یک بار در پاسخ ساخت نمایش داده می‌شوند؛ ذخیره آن‌ها مسئولیت شماست. برای محیط تولید CORS_ORIGINS را به دامنه دقیق سایت محدود کنید.

عیب‌یابی

خطای «توکن وارد شده معتبر نیست»

توکن را دوباره از BotFather کپی کنید. توکن تلگرام و بله الگوی عدد:رشته دارند؛ توکن روبیکا فقط حروف و ارقام است. اگر توکن معتبر است اما پلتفرم پاسخ نمی‌دهد، اتصال خروجی سرور و محدودیت شبکه را بررسی کنید.

خطای «بسته ورکر پیدا نشد»

ویزارد کد ورکر را از همان سایت دانلود و داخل بسته قرار می‌دهد؛ اگر شبکه اجازه نداد، فایل src/index.js از بسته‌های قبلی یا خروجی npm run build (مسیر dist/cloudflare-worker/index.js) را در پوشه بسته بگذارید و bash deploy.sh را دوباره اجرا کنید.

استقرار در گام webhook متوقف می‌شود

توکن ربات باید معتبر و دسترسی ثبت وب‌هوک داشته باشد. دامنه نهایی باید عمومی و با HTTPS باشد؛ آدرس محلی یا پورت غیراستاندارد پذیرفته نمی‌شود. پس از رفع، دکمه «بررسی سلامت» را بزنید یا استقرار جدید شروع کنید.

ورکر مستقر شده اما رسانه کار نمی‌کند

این محدودیت طراحی است: پردازش فایل و ffmpeg در محیط ورکر پشتیبانی نمی‌شود. برای ربات‌های دسته رسانه، Railway را انتخاب کنید.

داشبورد داده نشان نمی‌دهد

داشبورد محلی فقط نصب‌های همین مرورگر را نشان می‌دهد و داده زنده ندارد. برای آمار، کاربران و پیام همگانی، از صفحه کنسول مدیریت با ایمیل و گذرواژه‌ای که در .env بسته آمده وارد سرویس مستقرشده شوید. خطای ۴۰۱ یعنی نشست منقضی شده است؛ دوباره وارد شوید.
