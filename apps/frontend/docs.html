مستندات BotForge

از راه‌اندازی محلی تا استقرار خودکار روی Cloudflare Workers و Railway. همه دستورها و نمونه‌های کد قابل کپی هستند.

شروع راه‌اندازی سریع معماری مونوریپو تنظیمات محیطی محصول ۳۲ ربات و دسته‌ها ویزارد و استقرار خودکار عضویت اجباری مرجع مرجع API استقرار خودکار بسته استقرار امنیت عیب‌یابی

راه‌اندازی سریع

پروژه یک مونوریپوی Node.js با حداقل نسخه ۲۰٫۱۱ است. برای اجرای محلی، ابتدا وابستگی‌ها را نصب و سپس کنترل‌پلین را با درایور حافظه اجرا کنید. 

git clone https://github.com/amirsedighian071-stack/Botbuilder.git
cd Botbuilder
npm install
npm run typecheck
npm test

اجرای کنترل‌پلین با پایگاه‌داده حافظه برای آزمایش سریع:

PORT=8090 HOST=0.0.0.0 \
DATABASE_DRIVER=memory \
SECRET_MASTER_KEY=dev-master-key-change-me \
JWT_SECRET=dev-jwt-secret-change-me \
ADMIN_SEED_EMAIL=admin@botforge.local \
ADMIN_SEED_PASSWORD='ChangeMe#2026' \
npm run dev:api

سرو کردن رابط کاربری به‌صورت ایستا روی پورت ۴۱۷۳:

node scripts/serve-frontend.mjs --port 4173 --host 0.0.0.0
حساب مدیر اولیه ایمیل و گذرواژه از متغیرهای ADMIN_SEED_EMAIL و ADMIN_SEED_PASSWORD خوانده می‌شوند. پس از اولین ورود، گذرواژه را تغییر دهید: POST /api/auth/password

معماری مونوریپو

ساختار پوشه‌ها عمداً ساده و قابل نگهداری است:

packages/
  core/               ابزار مشترک، تنظیمات، اعتبارسنجی، ذخیره‌سازی
  platform-adapters/  آداپتور تلگرام، بله، روبیکا
  engine/             موتور اجرا، مدیریت ربات، صف کار، وب‌هوک
  bot-templates/      ۳۲ قالب ربات و کاتالوگ
apps/
  control-plane/      API Fastify + داشبورد + استقرار
  cloudflare-worker/  نسخه ورکر برای استقرار لبه‌ای
  frontend/           سایت چندصفحه‌ای ایستا (همین سایت)
scripts/              ساخت، تولید کاتالوگ، سرور پیش‌نمایش

لایه ذخیره‌سازی با یک قرارداد مشترک پیاده شده است: SQLite برای توسعه، PostgreSQL برای تولید و D1 برای ورکر. هر ربات شناسه مستقل دارد و همه پرس‌وجوها به همان شناسه محدود می‌شوند.

موتور و آداپتور

موتور، پیام‌های نرمال‌شده را دریافت می‌کند و منطق قالب را اجرا می‌کند. تفاوت‌های هر پلتفرم داخل آداپتور پنهان است؛ به همین دلیل یک قالب روی تلگرام، بله و روبیکا یکسان کار می‌کند. 

packages/platform-adapters/src/index.ts   // createAdapter, detectPlatformFromToken
packages/engine/src/manager.ts            // createBot, reload, webhookUrl, registerWebhook
packages/engine/src/runtime.ts            // اجرای دستورها، میان‌افزارها، محدودیت نرخ

تنظیمات محیطی

متغیرهای اصلی که برای اجرای تولید لازم است:

متغیرالزامیتوضیح

کلیدها را در مخزن نگذارید همه متغیرهای حساس از پنل میزبان یا فایل .env خارج از Git وارد می‌شوند. فایل .gitignore این مسیرها را پوشش می‌دهد.

۳۲ ربات و دسته‌ها

کاتالوگ در پنج دسته سازمان‌دهی شده و هر ربات دستورها و کلیدهای مشخص خود را دارد:

دستهتعدادربات‌ها
مالی و اطلاعاتی (A)۵قیمت طلا و ارز، رمزارز، اخبار، هشدار قیمت، آب‌وهوا، ماشین‌حساب مالی
فروش و کسب‌وکار (B)۷فروشگاه، پشتیبانی، نوبت‌دهی، اشتراک، بازاریابی، سفارش خدمات، CRM
دانلود و رسانه (C)۸دانلود اینستاگرام و یوتیوب، موسیقی، تبدیل صوت، فایل، فرمت، گفتار
هوش مصنوعی (D)۵دستیار هوشمند، مترجم، دستیار مطالعه، تولید محتوا، خلاصه‌ساز SSRF-safe
مدیریت و ابزار (E)۷مدیریت گروه، نظرسنجی، یادآور، کوتاه‌کننده لینک، فرم‌ساز، دوره، پایش سایت

فهرست دقیق با شماره، دستورها و کلیدها در صفحه کاتالوگ آمده است. منبع واقعی قالب‌ها در packages/bot-templates/src است و کاتالوگ سایت با node --import tsx scripts/generate-catalog.mjs از همان منبع ساخته می‌شود.

ویزارد و استقرار خودکار

ویزارد شش مرحله دارد و هر مرحله پیش از عبور، ورودی را اعتبارسنجی می‌کند:

  1. انتخاب قالب ربات از میان ۳۲ قالب.
  2. انتخاب پلتفرم، دریافت توکن از BotFather و اعتبارسنجی زنده با getMe.
  3. تعیین نام و شناسه یکتای ربات.
  4. ورود کلیدهای یکپارچه‌سازی با راهنمای دریافت هر کلید.
  5. انتخاب میزبان و اعتبارسنجی توکن Cloudflare یا Railway.
  6. بازبینی، ساخت بسته و «تأیید و استقرار خودکار».

دکمه‌های «دریافت API» همیشه به صفحه رسمی ساخت توکن لینک می‌شوند. پس از ورود توکن، در صورت اتصال به کنترل‌پلین، اعتبارسنجی خودکار انجام می‌شود؛ بدون اتصال، فقط قالب توکن بررسی و بسته استقرار دانلود می‌شود.

عضویت اجباری

در داشبورد هر ربات، بخش «عضویت اجباری» را باز کنید. هر کانال شامل پلتفرم، شناسه چت، عنوان، لینک دعوت و وضعیت الزامی بودن است. ربات پیش از اجرای دستور، عضویت کاربر را بررسی و در صورت نبود عضویت، لینک ورود می‌فرستد. 

curl -X PUT "https://SERVER/api/bots/BOT_ID/force-membership" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "enabled": true,
    "channels": [
      {
        "id": "ch_1",
        "platform": "telegram",
        "chatId": "@botforge_channel",
        "title": "کانال رسمی BotForge",
        "inviteLink": "https://t.me/botforge_channel",
        "required": true
      }
    ]
  }'

نمونه ساخت کلید API و ساخت ربات:

curl -X POST "https://SERVER/api/keys" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"ci-key","scopes":["bots:read","bots:write"]}'

curl -X POST "https://SERVER/api/bots" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"templateId":"gold-price","name":"قیمت طلا","slug":"gold-price","platform":"telegram","token":"123456:AA..."}'
کلید API فقط یک بار نمایش داده می‌شود در پاسخ ساخت کلید، مقدار کامل برمی‌گردد؛ آن را در جای امن ذخیره کنید. فهرست کلیدها فقط پیشوند را نشان می‌دهد.

استقرار خودکار

استقرار یک عملیات ناهمگام است: درخواست با کد ۲۰۲ پذیرفته می‌شود و گام‌ها در پس‌زمینه اجرا می‌شوند. برای پیگیری، مسیر وضعیت را تا رسیدن به healthy یا failed بخوانید. 

curl -X POST "https://SERVER/api/bots/BOT_ID/deploy" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "cloudflare",
    "credentials": { "apiToken": "CLOUDFLARE_TOKEN" },
    "integrationKeys": { "OPENAI_API_KEY": "sk-..." },
    "corsOrigins": "https://example.com"
  }'

پاسخ آغاز استقرار:

{
  "deployment": {
    "id": "dep_ab12cd34",
    "botId": "bot_9f...",
    "provider": "cloudflare",
    "status": "queued",
    "steps": [],
    "urls": {}
  },
  "statusUrl": "/api/bots/bot_9f.../deployments/dep_ab12cd34"
}

گام‌های واقعی

  1. validate — بررسی توکن پلتفرم و اعتبارنامه میزبان.
  2. database یا project — ساخت D1 و اجرای طرح‌واره، یا ساخت پروژه Railway.
  3. service — ساخت سرویس مقصد برای Railway.
  4. upload یا variables — بارگذاری ماژول ورکر و رمزها، یا تنظیم متغیرهای سرویس.
  5. domain — تخصیص دامنه workers.dev یا دامنه Railway.
  6. wait — انتظار برای پایان استقرار سرویس.
  7. webhook — ثبت آدرس /webhooks/<platform>/<botId>/<secret>.
  8. health — درخواست /health و ثبت کد پاسخ و تأخیر.

پاسخ وضعیت شامل گام‌ها، گزارش‌ها، آدرس‌ها و نتیجه سلامت است:

{
  "deployment": {
    "status": "healthy",
    "urls": {
      "app": "https://botforge-gold-price.account.workers.dev",
      "webhook": "https://botforge-gold-price.account.workers.dev/webhooks/telegram/bot_9f.../whsec_...",
      "health": "https://botforge-gold-price.account.workers.dev/health"
    },
    "health": { "ok": true, "status": 200, "latencyMs": 184 }
  }
}

دسترسی‌های لازم

توکن Cloudflare باید دسترسی Workers Scripts:Edit، D1:Edit و Account Settings:Read داشته باشد. توکن Railway از صفحه Account Tokens ساخته می‌شود و به پروژه‌های همان حساب دسترسی دارد.

محدودیت واقعی GitHub Pages این سایت ایستا است و نمی‌تواند به‌جای شما درخواست API بفرستد. اعتبارسنجی زنده و استقرار خودکار فقط با آدرس کنترل‌پلین در دسترس است. برای همین، ویزارد در حالت بدون سرور بسته استقرار و اسکریپت bash معتبر می‌سازد.

پس از استقرار، برای اطمینان از دریافت پیام، وب‌هوک را دوباره ثبت کنید:

curl -X POST "https://SERVER/api/bots/BOT_ID/webhook/register" \
  -H "Authorization: Bearer $ADMIN_TOKEN"

بسته استقرار

مسیر GET /api/bots/:id/deployments/:id/package چهار بخش برمی‌گرداند:

  • .env — متغیرهای غیرحساس و ماسک‌شده برای بازبینی.
  • .env.secrets — مقادیر حساس تولیدشده در سمت سرور.
  • deploy.sh — اسکریپت بازتولید همان استقرار.
  • webhook.txt — آدرس نهایی وب‌هوک.

فایل‌های حاوی رمز را فقط در محیط امن نگه دارید. توصیه می‌شود پس از دریافت، آن‌ها را در رمزنگاری‌شده ذخیره و از مخزن Git دور نگه دارید.

امنیت

  • توکن ربات با کلید اصلی رمزنگاری و فقط به‌صورت ماسک نمایش داده می‌شود.
  • پرس‌وجوهای SQL پارامتری‌اند؛ ورودی‌ها با zod اعتبارسنجی و متن‌ها پاک‌سازی می‌شوند.
  • محدودیت نرخ روی ورود، ارسال همگانی و وب‌هوک اعمال می‌شود.
  • خلاصه‌ساز لینک و درخواست‌های بیرونی با محافظ SSRF، DNS و بلاک شبکه خصوصی اجرا می‌شوند.
  • هر وب‌هوک دارای کلید مخفی در مسیر است و بدون آن پردازش نمی‌شود.
  • لاگ‌ها و رکوردهای حسابرسی، عملیات مدیران را ثبت می‌کنند.
کلیدهای API فقط یک بار در پاسخ ساخت نمایش داده می‌شوند؛ ذخیره آن‌ها مسئولیت شماست. برای محیط تولید CORS_ORIGINS را به دامنه دقیق سایت محدود کنید.

عیب‌یابی

خطای «توکن وارد شده معتبر نیست»

توکن را دوباره از BotFather کپی کنید. توکن تلگرام و بله الگوی عدد:رشته دارند؛ توکن روبیکا فقط حروف و ارقام است. اگر توکن معتبر است اما پلتفرم پاسخ نمی‌دهد، اتصال خروجی سرور و محدودیت شبکه را بررسی کنید.

خطای «بسته ورکر پیدا نشد»

سرور بسته ورکر را از مسیر dist/cloudflare-worker/index.js می‌خواند. ابتدا npm run build را اجرا کنید یا مسیر را با DEPLOY_WORKER_BUNDLE مشخص کنید.

استقرار در گام webhook متوقف می‌شود

توکن ربات باید معتبر و دسترسی ثبت وب‌هوک داشته باشد. دامنه نهایی باید عمومی و با HTTPS باشد؛ آدرس محلی یا پورت غیراستاندارد پذیرفته نمی‌شود. پس از رفع، دکمه «بررسی سلامت» را بزنید یا استقرار جدید شروع کنید.

ورکر مستقر شده اما رسانه کار نمی‌کند

این محدودیت طراحی است: پردازش فایل و ffmpeg در محیط ورکر پشتیبانی نمی‌شود. برای ربات‌های دسته رسانه، Railway را انتخاب کنید.

داشبورد داده نشان نمی‌دهد

ابتدا از اتصال به کنترل‌پلین مطمئن شوید. اگر آدرس درست است اما خطای ۴۰۱ می‌گیرید، توکن منقضی شده است؛ دوباره وارد شوید. در حالت بدون سرور، هیچ داده‌ای وجود ندارد و این رفتار طبیعی است.

خطای CORS در مرورگر

دامنه سایت را در CORS_ORIGINS سرور اضافه کنید و سرور را دوباره راه‌اندازی کنید. برای محیط آزمایش می‌توانید موقتاً از * استفاده کنید.
