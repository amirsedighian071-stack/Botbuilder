مستندات BotForge

این مستندات همه مراحل نصب، پیکربندی، استقرار و بهره‌برداری از BotForge را پوشش می‌دهد. BotForge یک مونوریپوی TypeScript است که موتور مشترک ربات، آداپترهای تلگرام/بله/روبیکا و ۳۲ قالب ربات کامل را در یک بسته ارائه می‌کند.

مسیر پیشنهادی مطالعه
  1. شروع سریع و ساختار مخزن را ببینید.
  2. متغیرهای محیطی و دیتابیس را تنظیم کنید.
  3. یکی از روش‌های استقرار را انتخاب کنید.
  4. مرجع API و پنل مدیریت را برای بهره‌برداری روزمره بخوانید.

معرفی

هر ربات در BotForge سه بخش دارد: قالب (BotDefinition) که منطق گفتگو را توصیف می‌کند، آداپتر پلتفرم که پیام‌ها را ترجمه می‌کند و رکورد ربات در پایگاه داده که توکن، وضعیت، تنظیمات و عضویت اجباری را نگه می‌دارد. موتور، قالب را روی آداپتر سوار می‌کند و چرخه دریافت به‌روزرسانی، مسیریابی، مدیریت وضعیت و پاسخ را انجام می‌دهد.

مفهومتوضیح
BotDefinitionقالب کامل ربات: منو، دستورها، اقدام‌ها، گام‌های گفتگو، کارهای زمان‌بندی‌شده و نیازمندی‌ها.
BotRuntimeنمونه فعال ربات در حافظه: آداپتر، تنظیمات لایه‌ای، سرویس‌ها، صف کار و محدودکننده نرخ.
BotManagerچرخه عمر ربات‌ها: ساخت، بازیابی توکن، ثبت وب‌هوک، بارگذاری و حذف.
Storageلایه داده یکپارچه برای PostgreSQL، SQLite و D1 با جداسازی داده هر ربات.

شروع سریع

پیش‌نیاز: Node.js نسخه ۲۰.۱۱ یا بالاتر و npm ۱۰. برای بخش رسانه، نصب ffmpeg توصیه می‌شود.

git clone https://github.com/amirsedighian071-stack/Botbuilder.git
cd Botbuilder
npm install

cp .env.example .env
# مقادیر SECRET_MASTER_KEY و JWT_SECRET را با کلید تصادفی جایگزین کنید

npm run migrate
npm run seed
npm run dev:api

پس از اجرا، بررسی سلامت در http://localhost:8080/health و ورود مدیر با ایمیل و گذرواژه‌ای که در مرحله بذر تعیین شده انجام می‌شود. برای دیدن سایت به‌صورت محلی npm run dev:web را اجرا کنید. 

npm run typecheck
npm test
npm run build

پایگاه داده

لایه ذخیره‌سازی یک اینترفیس دارد و سه پیاده‌سازی: PostgreSQL برای تولید، SQLite برای اجرای تک‌سرور و D1 برای ورکر. اسکریپت مهاجرت جدول‌ها و ایندکس‌ها را به‌صورت idempotent می‌سازد.

گزینه‌های استقرار

Railway

ساده‌ترین مسیر برای کنترل‌پلین کامل با PostgreSQL و پردازش رسانه.

Docker

اجرای قابل تکرار روی هر میزبان، با والیوم برای رسانه و فایل SQLite.

Cloudflare

ورکر سبک برای وب‌هوک، کاتالوگ و سلامت روی D1؛ سایت روی Pages.

استقرار روی Railway

  1. مخزن را به Railway متصل کنید؛ فایل railway.json و apps/control-plane/Dockerfile آماده است.
  2. یک سرویس PostgreSQL بسازید و متغیر DATABASE_URL را از آن بردارید.
  3. متغیرهای PUBLIC_BASE_URL، SECRET_MASTER_KEY، JWT_SECRET و کلیدهای سرویس‌ها را تنظیم کنید.
  4. دستور مهاجرت را یک‌بار اجرا کنید: npm run migrate.
  5. پس از دیپلوی، /health را بررسی و ربات‌ها را از پنل ثبت کنید.
railway init
railway add --database postgres
railway variables set PUBLIC_BASE_URL=https://your-app.up.railway.app
railway variables set SECRET_MASTER_KEY=...
railway variables set JWT_SECRET=...
railway up

ایمیج چندمرحله‌ای است: مرحله سازنده وابستگی‌ها را نصب و کد را بیلد می‌کند، مرحله اجرا فقط وابستگی تولیدی و کد کامپایل‌شده را دارد و با کاربر غیر ریشه اجرا می‌شود. برای ffmpeg متغیر ساخت INSTALL_FFMPEG=true را تنظیم کنید.

Cloudflare Worker و D1

ورکر برای دریافت وب‌هوک، کاتالوگ، سلامت و اجرای زمان‌بند طراحی شده است. ابتدا پایگاه D1 بسازید و شناسه آن را در apps/cloudflare-worker/wrangler.toml قرار دهید، سپس اسکیمای packages/core/src/storage/schema.ts را با wrangler d1 execute اعمال کنید. 

cd apps/cloudflare-worker
wrangler d1 create botforge
wrangler secret put SECRET_MASTER_KEY
wrangler secret put JWT_SECRET
wrangler deploy

# اسکیمای اولیه
wrangler d1 execute botforge --file=../../packages/core/sql/schema.sql --remote
آپلود و تبدیل رسانه در ورکر پشتیبانی نمی‌شود؛ مسیر /media در ورکر پیام راهنما برمی‌گرداند. برای ربات‌های دسته رسانه از کنترل‌پلین Node.js استفاده کنید.

استقرار سایت روی GitHub Pages

سایت کاملاً استاتیک است و بدون بیلد اجرا می‌شود. ورک‌فلوی .github/workflows/pages.yml پس از هر تغییر در شاخه اصلی، محتویات apps/frontend را منتشر می‌کند. در تنظیمات مخزن، Pages را روی GitHub Actions قرار دهید. 

npm run build
node scripts/generate-catalog.mjs
node scripts/serve-frontend.mjs --port 4173

مرجع API

همه مسیرهای /api نیازمند احراز هویت هستند: یا هدر Authorization: Bearer <jwt> از ورود مدیر، یا هدر X-API-Key با کلید ساخته‌شده در پنل. خطاها با ساختار یکسان و پیام فارسی برگردانده می‌شوند.

پنل مدیریت ربات

در داخل هر ربات، مدیر با دستور /admin یا دکمه «مدیریت» به پنل دسترسی دارد. این پنل روی موتور اجرا می‌شود و نیازی به رابط وب ندارد:

  • آمار زنده: تعداد کاربران، پیام‌های ۲۴ ساعت، خطاهای هفته و کارهای در صف.
  • مدیریت کاربران: جست‌وجو، تغییر نقش، مسدودسازی و یادداشت.
  • پیام همگانی: با نمایش پیشرفت و نرخ محدودشده.
  • تنظیمات: ویرایش کلید/مقدار با ماسک‌کردن مقادیر حساس.
  • وضعیت ربات: فعال، متوقف موقت، حالت تعمیر و غیرفعال.
  • نیازمندی‌ها: نمایش وضعیت هر کلید خارجی و راهنمای دریافت آن.

کاربران، نقش‌ها و پیام همگانی

نقش‌ها: owner، admin و user. فقط نقش‌های مدیر به پنل داخل ربات دسترسی دارند و می‌توانند پیام همگانی بفرستند. پیام همگانی در صف ذخیره می‌شود؛ در صورت خطای موقت، تلاش مجدد نمایی انجام می‌شود و کاربران مسدود یا حذف‌شده نادیده گرفته می‌شوند.

فهرست ربات‌ها و دستورها

جدول زیر از قالب‌های واقعی مخزن تولید می‌شود و با هر تغییر در ربات‌ها به‌روزرسانی می‌گردد.

امنیت

  • توکن‌ها: رمزنگاری AES-256-GCM با کلید مشتق‌شده از SECRET_MASTER_KEY؛ نمایش فقط به‌صورت ماسک.
  • وب‌هوک: مسیر شامل secret یکتا و بررسی هدر اختصاصی تلگرام؛ درخواست نامعتبر با ۴۰۱ رد می‌شود.
  • دسترسی: JWT کوتاه‌عمر برای مدیران، کلید API هش‌شده با SHA-256 و دامنه دسترسی مشخص.
  • ورودی: اعتبارسنجی Zod برای همه بدنه‌ها، پاک‌سازی متن و escape در پاسخ‌های HTML ربات.
  • دیتابیس: همه کوئری‌ها پارامتری هستند؛ شناسه ربات در هر شرط اجباری است.
  • SSRF: بلاک شبکه‌های خصوصی، متادیتای ابری و پورت‌های غیرمجاز با اجازه‌نامه دامنه.
  • نرخ: محدودیت سراسری HTTP، محدودیت به‌ازای کاربر در موتور و باکت توکنی در ارسال همگانی.

پایش و سلامت

مسیر /health وضعیت پایگاه داده، تعداد کارهای در صف و ربات‌های بارگذاری‌شده را برمی‌گرداند و برای liveness probe مناسب است. رخدادهای هر ربات در جدول events ثبت و از طریق /api/bots/:id/events قابل مشاهده است. 

curl -s https://botforge.example.com/health | jq .
curl -s -H "Authorization: Bearer $TOKEN" \
  https://botforge.example.com/api/system/stats | jq .

عیب‌یابی

وب‌هوک ثبت نمی‌شود

PUBLIC_BASE_URL باید دامنه عمومی با HTTPS باشد. برای تلگرام دامنه باید گواهی معتبر داشته باشد و پورت غیراستاندارد پذیرفته نمی‌شود. پاسخ POST /api/bots/:id/webhook/register وضعیت را برمی‌گرداند.

ربات پاسخ نمی‌دهد

وضعیت ربات را بررسی کنید؛ در حالت maintenance یا disabled پاسخ ارسال نمی‌شود. رخدادهای webhook.rejected نشانه ناسازگاری secret است و webhook.error جزئیات خطای پردازش را دارد.

خطای «کلید تنظیم نشده است»

ربات‌های هوش مصنوعی، گفتار، اخبار و قیمت به کلید خارجی نیاز دارند. کلید را در پنل مدیریت ربات یا در متغیرهای محیطی تنظیم کنید؛ وضعیت هر کلید در پاسخ GET /api/bots/:id/settings آمده است.

تبدیل ویدیو یا صوت شکست می‌خورد

وجود ffmpeg را با ffmpeg -version بررسی کنید. سقف حجم ورودی با MAX_UPLOAD_MB کنترل می‌شود و پردازش بیش از دو دقیقه متوقف می‌شود.

صف کار پیش نمی‌رود

در کنترل‌پلین، صف با اجرای سرور شروع می‌شود. در ورکر، زمان‌بند cron وظیفه اجرای صف را دارد. کارهای ناموفق با تأخیر نمایی دوباره تلاش می‌شوند و پس از سقف تلاش، وضعیت dead می‌گیرند.
